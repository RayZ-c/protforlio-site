# Project brief

Copy this, fill it in, hand it to an agent with: **"Build a case study from this
brief."** Everything else — structure, icons, tags, panels, media wiring,
registration on the index — is the agent's job, governed by
`project-context/authoring-a-case-study.md`.

Write in rough notes. Do not write prose. Turning notes into prose is the part
that gets done for you; only you know the facts.

## The hard part

The thing that took longest or that you'd talk about in an interview. What was
the problem, what did you try, what did you land on?

## Code worth showing

Paste 1–3 short excerpts (15 lines max each), and say for each one what the
interesting decision is. If you have none, say so — a case study without code
is fine, one with dumped boilerplate is not.

## Numbers

Anything measurable: frame budget, load time, file size, downloads, jam
placement, players, review score. **If you have none, write "none" — do not let
anything be invented.**
